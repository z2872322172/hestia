# 家政服务预约平台脚手架搭建说明书

> 本文是完整目标脚手架。当前项目尚未进入业务模块阶段，第一阶段只执行 [06-第一阶段最小骨架集成.md](./06-第一阶段最小骨架集成.md)，不要提前创建账号、订单、人员和服务项目等业务模块。

> 业务口径说明：当前项目采用单公司自营模式。脚手架中的商家、入驻、抢单和多商家权限内容属于历史目标结构，实际业务模块以 [modules/README.md](./modules/README.md) 为准。

## 2. 不可修改的架构约束

执行 AI 必须遵守：

1. 使用单个 Spring Boot 应用，不拆微服务。
2. 使用 Maven 单模块工程，按 Java 包划分业务模块，不创建多个 Maven 子模块。
3. MySQL 是订单、支付、排班、人员、文件元数据和审计的唯一事实来源。
4. Redis 用于缓存、Refresh Token、限流、在线状态、GEO 和分布式锁，不作为唯一业务状态存储。
5. RocketMQ 只处理事务提交后的异步事件，不参与下单、锁时段和支付确认的强一致事务。
6. MinIO 私有桶不允许匿名访问，文件必须通过权限检查或短期签名 URL 访问。
7. 高德地图只通过后端 `MapProvider` 适配器调用，业务代码不得直接依赖高德 SDK 或 HTTP 细节。
8. 所有数据库表结构通过 Flyway 创建，禁止使用 Hibernate 或 MyBatis-Plus 自动建表。
9. 不在代码、配置文件、测试数据和 README 中写入真实密码、JWT 密钥、MinIO Secret 或高德 Key。
10. 不实现前端页面，只提供 REST API、WebSocket 契约和 Swagger 文档。


### 7.2 模块规则

- 只有 `api` 可以使用 Spring MVC 注解。
- 只有 `application` 可以声明 `@Transactional`。
- `domain` 不依赖 Controller、Mapper 和外部 SDK。
- `infrastructure` 实现外部适配器和数据库访问。
- `common` 不依赖任何业务模块。
- 业务模块不能直接调用其他模块的 Mapper。
- `admin` 可以调用其他模块公开的查询服务，但不能被其他业务模块依赖。
- `ordering` 和 `dispatch` 可以共享订单公开查询接口，但不能循环依赖。

必须添加 ArchUnit 测试验证：

- `common` 不依赖业务包。
- `api` 不直接依赖 `infrastructure.mapper`。
- 业务模块之间没有直接 Mapper 引用。
- `domain` 不依赖 Spring Web。

### 7.3 与图片式目录的对应关系

本项目采用 **Package by Feature / Vertical Slicing**。图片中的结构是：

```text
com.xxx
├─ alarmdevice/
├─ appgateway/
│  ├─ controller/
│  ├─ entity/
│  ├─ mapper/
│  ├─ service/
│  └─ vo/
├─ capacitymodule/
├─ command/
└─ common/
```

本项目采用同样的垂直分包思想，但为增强企业级可维护性，在模块内部增加了 `api`、`application`、`domain` 和 `infrastructure` 边界：

| 图片式目录 | 本项目目录 |
| --- | --- |
| `appgateway/controller` | `appgateway/api/customer`、`appgateway/api/worker`、`appgateway/api/admin` |
| `appgateway/service` | `appgateway/application/service` |
| `appgateway/entity` | `appgateway/infrastructure/persistence/entity` |
| `appgateway/mapper` | `appgateway/infrastructure/persistence/mapper` |
| `appgateway/vo` | `appgateway/vo` |
| 模块内业务流程 | `appgateway/application` |
| 模块内状态、规则和枚举 | `appgateway/domain` |
| 外部系统适配 | `appgateway/infrastructure/adapter` |

以订单模块为例：

```text
ordering/
├─ api/
│  ├─ customer/
│  ├─ worker/
│  ├─ merchant/
│  └─ admin/
├─ application/
│  ├─ booking/
│  ├─ dispatch/
│  ├─ fulfillment/
│  ├─ payment/
│  └─ query/
├─ domain/
│  ├─ order/
│  ├─ assignment/
│  ├─ fulfillment/
│  ├─ payment/
│  └─ policy/
├─ dto/
├─ vo/
└─ infrastructure/
   ├─ persistence/
   │  ├─ entity/
   │  ├─ mapper/
```

执行约束：

- 不创建一个全局的 `controller` 目录承载所有业务接口。
- 不创建一个全局的 `service` 目录承载所有业务逻辑。
- 不创建一个全局的 `mapper` 目录承载所有模块数据库访问。
- 每个业务模块必须拥有自己的 `api`、`application`、`domain`、`dto`、`vo` 和 `infrastructure`。
- `common` 只放跨模块技术能力，不放订单、人员、排班等具体业务。

## 10. RocketMQ 骨架

### 10.1 配置

创建：

```text
RocketMqProperties
RocketMqProducerConfig
RocketMqConsumerConfig
DomainEventPublisher
OutboxEventRelay
IdempotentConsumerService
```

使用 `rocketmq-client-java`，手工创建 Producer 和 Consumer。

### 10.2 事件模型

```text
DomainEvent<T>
EventType
AggregateType
EventOutbox
ConsumerMessage
```

事件信封字段：

```text
eventId
eventType
aggregateType
aggregateId
occurredAt
traceId
version
payload
```

### 10.3 初始 Topic

```text
HK_ORDER_EVENT
HK_DISPATCH_EVENT
HK_PAYMENT_EVENT
```

### 10.4 初始消费者

```text
GID_DISPATCH_CANDIDATE
GID_REALTIME_NOTIFY
GID_STATISTICS
```

### 10.5 Outbox

业务事务写 `event_outbox`，Relay 定时发送 RocketMQ。

Relay 要求：

- 批量读取 PENDING 事件。
- 使用 `SELECT ... FOR UPDATE SKIP LOCKED` 或等价机制。
- 支付和订单一类的消息不得无限重试。
- 发送失败写 `last_error` 和 `next_retry_at`。
- 成功后更新 `SENT`。
- 事件必须带唯一 `eventId`。

### 10.6 消费幂等

每个消费者先检查并写入 `consumer_message`，唯一键为：

```text
(consumer_group, message_id)
```

重复消息直接成功返回。消费者失败抛出异常，由 RocketMQ 重试，超过阈值的消息进入死信处理流程。

### 10.7 脚手架验收事件

提供一个仅用于 smoke test 事件：

```text
eventType: SCAFFOLD_PING
topic: HK_ORDER_EVENT
consumer: GID_STATISTICS
```

消费者收到后写一条测试记录。该测试不得参与真实业务统计。

创建：

```text

WebSocketSessionRegistry
RealtimePushService
PresenceService
```

连接：

```text

```

要求：

- 单实例使用 Simple Broker。
- 多实例扩展预留 Redis Pub/Sub 接口，不在脚手架阶段实现完整广播。

## 20. 完成定义

以下条件全部满足才算脚手架完成：

1. `docker compose` 可以启动 MySQL、Redis、MinIO、RocketMQ。
2. `mvn clean verify` 通过。
3. Spring Boot 在 `local` profile 启动成功。
4. Flyway 从空数据库创建全部脚手架表。
5. `/actuator/health` 返回数据库、Redis、MinIO 和 RocketMQ 状态。
6. Swagger UI 可以打开。
7. 登录、刷新和退出接口有可测试骨架。
8. Refresh Token 能在 Redis 中创建、刷新和撤销。
9. `SCAFFOLD_PING` 事件能写入 outbox、发送 RocketMQ、被一个消费者幂等消费。
10. MinIO 公开桶和私有桶可上传、生成签名 URL。
11. Mock 地图可以在无外网环境工作，Amap Provider 配置可切换。
12. WebSocket 连接可通过 JWT 建立并存续。
13. ArchUnit 模块边界测试通过。
14. README 包含一键启动、环境变量、接口和排错说明。
15. 代码中没有真实 Secret、默认生产管理员或自动建表配置。

## 21. 执行 AI 禁止事项

执行 AI 不得：

- 拆分 Maven 子模块或微服务。
- 为了实现“完整”而一次性写完全部业务页面和接口。
- 使用自动建表替代 Flyway。
- 用 Redis 存唯一订单状态。
- 用 RocketMQ 代替数据库事务。
- 用 MinIO 公开桶保存证件。
- 在 Controller 直接调用 Mapper、Redis、RocketMQ、MinIO 或高德接口。
- 使用 `latest` Docker 镜像。
- 在代码中硬编码账号、密码、Token、Key 和 Bucket Secret。
- 删除或修改已经执行过的 Flyway 迁移文件。
- 把真实地址、电话和证件写入日志或 MQ 消息。
- 在没有兼容性验证的情况下使用未经验证的 RocketMQ Spring Boot Starter。
