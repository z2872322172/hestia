# 家政服务预约平台业务模块实施施工总说明

## 1. 文档用途

本文是后端项目从技术骨架进入业务开发阶段的施工总说明，用于回答：

- 先实现什么模块。
- 每个模块交付哪些代码和数据库迁移。
- 模块之间通过什么接口协作。
- 每个阶段完成到什么程度可以进入下一阶段。
- 如何验证并发、幂等、权限和业务流程。
- 如何从空数据库启动并演示完整业务闭环。

本文不重复业务规则。业务细节以 `docs/modules/` 为准。

## 2. 文档优先级

发生冲突时按以下顺序执行：

1. 用户当前明确要求。
2. `hestia-backend/AGENTS.md`。
3. 本文中的施工顺序和验收门槛。
4. `docs/modules/` 中的业务模块详细设计。
5. `docs/06-第一阶段最小骨架集成.md` 中的技术基础要求。
6. 其他历史设计文档。

如果业务设计和施工顺序冲突，先修正设计文档，再修改本文。

## 3. 当前项目起点

当前状态：

```text
已有后端目录骨架
```

施工不能直接从订单模块开始。必须先完成可运行技术骨架，再按模块依赖顺序推进。

## 4. 总体施工原则

1. 一个 Maven 工程，一个 Spring Boot 应用。
2. 按业务模块垂直分包，不建立全局平铺的 Controller、Service 和 Mapper。
3. 所有数据库结构由 Flyway 管理。
4. 所有业务状态通过应用服务修改，不在 Controller 中直接改表。
5. 跨模块只调用公开应用服务、查询服务或 Port。
6. 每个阶段必须执行测试和验收，不能全部写完再补。
7. 每个模块的实体、DTO、VO、Mapper、迁移、接口和测试必须成套交付。
8. 生产配置不得包含默认账号、固定验证码或真实密钥。
9. 文档、数据库迁移、接口和测试必须同步更新。
10. 未完成验收的模块不能作为后续模块的稳定依赖。

### 6.1 Controller

- 只做协议转换、参数校验、权限入口。
- 不直接调用 Mapper、Redis、消息队列或文件 SDK。
- 不计算价格，不修改状态。

### 6.2 Application Service

- 一个公开方法对应一个明确用例。
- 负责事务、幂等、权限和数据范围。
- 负责调用其他模块的公开服务。
- 负责编排跨模块一致性。

### 6.3 Domain

- 放状态机、计价规则、时段规则、匹配规则和履约规则。
- 不依赖 Spring MVC、MyBatis Mapper 和外部 SDK。

### 6.4 Infrastructure

- 放 Entity、Mapper、Repository、Redis、MQ、文件和外部适配器。
- 不承载业务状态判断。

## 12. 核心施工顺序

### 12.1 消费者注册

```text
identity 创建账号
-> 绑定 CUSTOMER
-> customer 创建客户档案
-> 返回登录 Token
```

验收：

- 手机号唯一。
- 密码 BCrypt。
- 账号、角色和客户档案同一事务。
- 重复注册被拒绝。

### 12.2 地址和服务范围

```text
customer 创建地址
-> location 匹配服务区域
-> 写回 service_area_id 和匹配状态
```

验收：

- 默认地址唯一。
- 跨用户地址不可见。
- 服务区域外地址不能生成下单快照。

### 12.3 服务目录

```text
运营创建服务项目
-> 配置价格和标准
-> 发布
-> 消费者查询
-> 价格预览
```

验收：

- 下架服务不能下单。
- 价格由服务端计算。
- 订单保存价格和标准快照。

### 12.4 人员与排班

```text
创建人员
-> 邀请账号
-> 审核技能和证书
-> 分配服务区域
-> 发布排班
-> 生成 worker_slot
```

验收：

- 未审核人员不能派单。
- 同一人员同一时间窗只有一个 slot。
- 请假不会静默覆盖已支付订单。

### 12.5 下单和锁时段

```text
校验客户、地址和服务区域
-> 目录报价
-> 查询可用人员
-> 生成候选人
-> 锁定时段 HELD
-> 创建订单 PENDING_PAYMENT
-> 创建派单任务 WAITING_PAYMENT
```

验收：

- 并发下单只有一个成功。
- 订单失败时时段不残留。
- 重复幂等键不创建第二个订单。

### 12.6 支付和激活派单

```text
创建支付记录
-> 模拟支付成功
-> 订单 CONFIRMED
-> 时段 BOOKED
-> 派单 PENDING_ACCEPT
-> 通知服务人员
```

验收：

- 重复支付只有一条成功记录。
- 重复回调不重复更新订单。
- 支付超时取消订单并释放时段。

### 12.7 接单和改派

```text
人员接受 -> 分配 ACCEPTED
人员拒绝 -> 自动下一候选人
候选人耗尽 -> MANUAL_REQUIRED
运营改派 -> 重新锁时段
```

验收：

- 拒单不取消已支付订单。
- 改派保留历史。
- 仅当前分配人员可推进履约。

### 12.8 履约

```text
出发
-> 签到
-> 开始服务
-> 完成检查项和证据
-> 申请完成
-> 客户确认或自动确认
```

验收：

- 未签到不能开始服务。
- 必填检查项未完成不能申请完成。
- 服务人员不能代替客户确认。

## 14. 审计字段施工要求

普通可变业务表必须包含：

```text
created_at
created_by_account_id
updated_at
updated_by_account_id
version
```

实现方式：

```text
MyBatis-Plus MetaObjectHandler
-> 从当前安全上下文获取账号 ID
-> 创建时填充 created_by
-> 更新时填充 updated_by
```

系统任务没有登录账号时，人员字段可以为空，但必须记录：

```text
operation_source = SYSTEM
trace_id
```

日志、支付回调、状态历史和证据表按追加表处理，不强行增加修改人。

## 19. 全链路验收

从空数据库启动后完成：

```text
消费者注册
-> 创建地址
-> 查询服务
-> 查询可用时间
-> 下单并锁时段
-> 支付
-> 人员接受
-> 人员出发
-> 签到
-> 开始服务
-> 完成检查项和照片
-> 申请完成
-> 客户确认
-> 客户评价
-> 发起售后
-> 运营处理
```

必须额外验证：

- 同一时段并发下单只有一个成功。
- 重复支付和回调不产生重复资金记录。
- 人员拒单后订单仍保持已支付和有效。
- 运营只能访问授权区域。
- 完整地址和手机号不会出现在日志和通知正文。
