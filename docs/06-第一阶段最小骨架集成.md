# 第一阶段最小骨架集成

## 1. 当前阶段目标

当前不做家政业务模块，不设计账号、订单、排班、工作人员和支付业务代码。

本阶段只完成可运行的工程技术骨架：

```text
一个 Spring Boot 应用
一个 Maven 工程
MySQL 可用
Redis 可用
RocketMQ 可用
MinIO 可用
高德地图适配器可切换
WebSocket 可用
Actuator、Swagger、统一响应、异常和 traceId 可用
```

完成本阶段后，另一个 AI 才能在此基础上逐步添加业务模块。

## 2. 当前阶段明确不做

- 不创建 `identity`、`customer`、`organization`、`catalog`、`scheduling`、`ordering`、`dispatch`、`fulfillment`、`servicequality` 等业务模块。
- 不创建账号、用户、工作人员、商家、服务项目、预约、订单、支付、评价和投诉表。
- 不实现登录注册和真实 JWT 用户体系。
- 不实现订单状态机、预约排班和抢单逻辑。
- 不实现前端页面。
- 不把示例健康检查接口伪装成业务接口。

可以先保留业务模块目录规范，但第一阶段不生成业务类和业务表。

## 6. 技术基础表

第一阶段 Flyway 只创建技术表：

```text
event_outbox
consumer_message
idempotency_record
file_object
audit_log
system_config
```

可以创建 `schema_history` 由 Flyway 自动管理。

不创建：

```text
account
customer_profile
worker_profile
service_item
booking_order
payment_record
review
complaint
```

### 6.1 `event_outbox`

用于技术冒烟事件和后续可靠消息。

### 6.2 `consumer_message`

用于消费者幂等。

### 6.3 `idempotency_record`

用于后续创建订单和支付接口幂等，技术骨架先建表。

### 6.4 `file_object`

用于 MinIO 文件元数据，第一阶段只用于冒烟上传。

### 6.5 `audit_log`

记录本阶段系统配置变更和后续敏感操作。

### 6.6 `system_config`

保存非敏感系统参数，比如地图 provider 名称和文件大小限制。

## 7. 基础设施配置

### 7.1 MySQL

- 数据源从环境变量读取。
- Flyway 在启动时自动执行迁移。
- 关闭 MyBatis-Plus 自动建表。
- 健康检查接入 Actuator。

### 7.2 Redis

- 连接配置从环境变量读取。
- Spring Data Redis 负责缓存。
- Redisson 负责后续锁能力，本阶段只验证连接。
- key 前缀使用 `app:`。
- 健康检查接入 Actuator。

### 7.3 RocketMQ

- 使用 `rocketmq-client-java`。
- 手工创建 Producer 和 Consumer。
- 不引入 RocketMQ Spring Boot Starter。
- 本阶段 Topic：`HK_TECH_EVENT`。
- 本阶段消费者组：`GID_TECH_SMOKE`。
- 本阶段事件：`SCAFFOLD_PING`。

冒烟流程：

```text
POST /api/v1/system/smoke/event
  -> 写 event_outbox
  -> 返回 eventId

Outbox Relay
  -> 发送 HK_TECH_EVENT

GID_TECH_SMOKE
  -> 写入 consumer_message
  -> 把处理结果写入 system_config 或内存查询接口
```

### 7.4 MinIO

- 两个桶：公开桶和私有桶。
- 本阶段由 Docker 初始化桶。
- 后端提供对象存在检查和签名 URL 生成。
- 冒烟接口只允许 `local` 和 `demo` profile。

### 7.5 高德地图

- `MapProvider` 接口。
- `MockMapProvider` 默认启用。
- `AmapMapProvider` 仅在配置 Key 时启用。
- 本阶段只验证地理编码或健康检查，不接入业务地址。

### 7.6 WebSocket

- 端点 `/ws`。
- 本阶段允许发送 `SYSTEM_PING`。
- 客户端发送到 `/app/system.ping`，订阅 `/topic/system.ping`。
- 业务派单通知不实现。
- 后续业务模块使用 `/user/queue/dispatch`。

## 8. 第一阶段 API

只创建系统集成接口：

```text
GET  /api/v1/system/ping
GET  /api/v1/system/integrations
POST /api/v1/system/smoke/event
POST /api/v1/system/smoke/file
GET  /api/v1/system/smoke/geo
GET  /api/v1/system/smoke/event/{eventId}
GET  /v3/api-docs
GET  /swagger-ui/index.html
GET  /actuator/health
```

这些接口只用于验证骨架，不作为业务 API。

生产环境：

- 关闭 `/api/v1/system/smoke/**`。
- 只保留受保护的健康和指标接口。

## 9. 第一阶段安全

- 引入 Spring Security。
- `/actuator/health`、Swagger、系统 ping 在 `local` 可匿名访问。
- `prod` 关闭 smoke 接口。
- 不创建默认账号。
- 不实现登录、JWT 和 Refresh Token 业务。
- JWT 依赖可以留到第二阶段 `identity` 模块再加入。

## 12. 完成定义

第一阶段完成必须满足：

1. 应用可以在 `local` profile 启动。
2. MySQL Flyway 执行成功。
3. Redis PING 和缓存读写成功。
4. RocketMQ 冒烟事件能被消费者收到。
5. MinIO 桶存在且可生成签名 URL。
6. Mock 地图可用，Amap Provider 可配置切换。
7. WebSocket 可以连接并收到 `SYSTEM_PING`。
8. Swagger 可以打开。
9. ArchUnit 技术边界测试通过。
10. `mvn clean verify` 通过。
11. 没有业务模块、业务表、默认账号和假业务接口。
